# Aura Score

악기 구성과 분위기, 템포를 고르면 GPT 가 오케스트라 총보를 써 주는 앱.

- **악보 생성**: OpenAI `gpt-6-sol` (Responses API, Structured Outputs). `.env` 에서 바꿀 수 있습니다.
- **악보 표시**: OpenSheetMusicDisplay 2.1.3, MusicXML 다운로드
- **재생**: smplr 1.0 + General MIDI 사운드폰트(MusyngKite), 악보 위 커서가 따라감
- **로그인**: Firebase Authentication, 이메일/비밀번호

## 화면

| 경로 | 화면 | 로그인 |
|---|---|---|
| `/` | 홈 | 불필요 |
| `/signup`, `/login` | 회원가입, 로그인 (`?next=/경로` 면 로그인 후 그리로) | — |
| `/scores/new` | 입력 방식 고르기 → `?mode=simple` 또는 `?mode=detailed` 폼과 결과 악보 | **필요** |
| `POST /api/scores` | 폼 → GPT → MusicXML | **필요** |

입력은 두 가지 방식이고, 서버에서는 같은 요청 하나(`orchestra.Request`)로 합쳐집니다.

- **간단하게** — 버튼만. 작곡가 스타일 7종(바로크·고전·베토벤·낭만·인상주의·영화음악·게임/애니 OST),
  규모(스타일에 맞게 / 작게 ~10명 / 중간 ~30명 / 크게 60명+), 분위기(최대 2개), 빠르기 3단계,
  주인공 악기(선택), 길이 8/16/32마디, 한 줄 메모. 스타일이 악기를, 규모가 인원을 정하고(`orchestra.scaled`),
  고른 결과는 폼에 "플루트 2 · … · 현악 6-5-4-3-2 (총 33명)" 처럼 바로 보입니다.
  난이도는 중급, 조성·박자는 GPT 가 고릅니다.
- **자세하게** — 악기 15종의 인원(관악은 한 줄을 나눠 쓰는 연주자 수, 현악은 파트 인원),
  조성·박자(직접 또는 맡기기), 곡 형식(A / AB / ABA / 론도), 주인공 악기(선택), 템포 BPM, 마디 수(4~48), 스타일(선택),
  난이도, 분위기, 추가사항. 고른 조성·박자는 스키마에서 값 하나짜리 enum 이 되어 GPT 가 바꿀 수 없습니다.

현악 인원은 악보 모양을 거의 바꾸지 않습니다 (몇 명이든 한 줄). 1명이면 솔로(겹음 2개까지),
10명 이상이면 세 갈래 divisi 까지 허용하는 식으로 동시에 낼 수 있는 음 수에만 반영됩니다.

## 준비

```bash
cp .env.example .env
```

`.env` 에 채울 것:

1. **Firebase Admin 키** — Firebase Console > 프로젝트 설정 > 서비스 계정 > 새 비공개 키 생성 →
   `serviceAccountKey.json` 으로 이 폴더에 저장. (`.gitignore` 에 들어 있습니다. 절대 커밋하지 마세요.)
2. **Firebase 웹 설정** — 프로젝트 설정 > 일반 > 내 앱 > 웹 앱의 `apiKey` / `authDomain` / `projectId`.
   키 파일과 같은 프로젝트여야 합니다. 다르면 화면 위 배너가 알려 줍니다.
3. **이메일/비밀번호 로그인 켜기** — Authentication > Sign-in method > 이메일/비밀번호 > 사용 설정.
4. **OPENAI_API_KEY** — https://platform.openai.com/api-keys 에서 만든 키.
   `OPENAI_MODEL`(기본 `gpt-6-sol`) 과 `OPENAI_REASONING_EFFORT`(기본 `medium`) 는 선택입니다.
5. **FLASK_SECRET_KEY** — `python3 -c "import secrets; print(secrets.token_hex(32))"` 로 만든 값.

설정이 덜 끝나면 화면 위에 무엇이 남았는지 배너로 뜹니다.

`gpt-6-sol` 기준으로 16마디 13파트 한 곡에 약 50초가 걸렸습니다. 곡마다 걸린 시간, 토큰 수,
자동 수정 개수가 서버 로그에 `score: ...` 한 줄로 남습니다.

## 실행

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python app.py
```

http://localhost:5002 (5000 은 macOS AirPlay, 5001 은 Music Aura)

`.env` 는 프로세스가 뜰 때 한 번만 읽습니다. 값을 고쳤으면 서버를 완전히 껐다 켜세요.

## 동작 방식

**GPT 는 MusicXML 을 쓰지 않습니다.** 오케스트라 총보를 MusicXML 로 쓰면 수천 줄이고,
어디 한 군데만 틀려도 파일 전체가 깨집니다. 대신 마디마다 짧은 문자열 하나를 씁니다.

```
"@p C4:4( D4:8 E4:8 F4:4 G4:4)"     셈여림 p, 이음줄 시작, 4분·8분음표…
"G4+B4:2. r:4"                      화음(점2분) + 4분쉼표
"E5:2~ E5:8 D5:8 C5:4"              붙임줄
"R"                                 온마디 쉼표
```

음높이는 모두 실음(Score in C)입니다. 서버(`musicxml.py`)가 이 문자열을 읽어 MusicXML 로
바꾸면서 모델이 실제로 자주 내는 실수를 고칩니다:

- 마디 박자 합이 모자라면 쉼표로 채우고, 넘치면 마디선에서 자릅니다.
- 악기 음역 밖의 음은 옥타브를 옮겨 안으로 넣습니다 (초급은 더 좁은 음역).
- 편성 인원보다 많은 화음은 바깥 성부(맨 위·맨 아래)만 남깁니다.
- 음이 다른 붙임줄, 짝이 없는 이음줄은 지웁니다.
- 마디 수가 다르거나 빠진 파트는 쉼표로 채우고, 구간 길이의 합이 틀리면 전체 마디 수에 맞춥니다.
- 직전과 같은 셈여림 기호는 지웁니다 (두 마디 넘게 쉬고 들어올 때는 남깁니다).

고친 개수는 악보 위에 "N군데를 자동으로 고쳤습니다" 로 표시됩니다.

**설계도를 먼저 쓰고, 구간 단위로 씁니다.** 처음에는 GPT 가 계획 없이 악기별로 처음부터 끝까지 썼고,
32마디를 달라고 하면 네 화음을 여덟 번 돌렸습니다. 지금은 응답 형식의 순서가 곧 작업 순서입니다.

1. `lead` — 곡을 이끄는 주인공 악기. 사용자가 고르지 않으면 GPT 가 정합니다.
2. `outline` — 구간마다 역할(도입·주제·대비·전개·솔로·절정·재현·종결), 마디 수, 선율 악기, 짜임,
   반주 종류, 셈여림, 그리고 "여기서 새로 일어나는 일" 한 문장.
3. `sections` — 그 설계대로 구간 하나씩, 모든 악기를 함께.

지시문은 되돌아오는 선율을 반드시 바꾸게 하고, 이웃한 구간이 같은 반주를 쓰지 못하게 하고,
16마디 이상이면 주인공 악기에게 솔로 구간을 줍니다. 솔로와 절정의 위치는 요청마다 여섯 가지 서사 형태
(`orchestra.SHAPES`) 중 하나를 무작위로 줘서, 곡마다 같은 틀이 나오지 않게 합니다.
설계도는 결과 화면에 "곡의 흐름" 으로 보이고, 악보에는 구간 기호와 Solo / tutti 로 들어갑니다.
솔로 구간은 재생할 때 합주 샘플 대신 솔로 악기 샘플로 납니다.

서버는 반복을 숫자로 잽니다(`musicxml._repetition`): 한 파트 안에서 앞 마디를 그대로 베낀 마디에 든
음의 비율. 같은 조건의 32마디 두 곡에서 59% → 21~24%, 33% → 11~15% 로 줄었습니다. 리듬만 같은
마디의 비율은 74~82% 로 여전히 높은데, 한 구간 안에서 반주가 같은 리듬을 유지하는 것까지 세기 때문입니다.

**스키마로 막을 수 있는 건 스키마로 막습니다.** 응답의 악기 이름은 고른 악기만,
조성은 난이도에 맞는 것만(초급은 조표 2개 이하) 나오도록 요청마다 JSON 스키마를 새로 만듭니다.

**기보 규칙.** 피콜로와 콘트라베이스는 관례대로 옥타브를 옮겨 적고, 음자리표는 파트의 음역을
보고 고릅니다 (비올라 알토, 첼로가 높으면 테너 등). 6/8 박자에서는 점4분음표를 한 박으로
템포를 표시합니다.

**재생.** 서버는 악보를 쓰면서 이미 모든 음의 실제 높이와 길이를 알고 있으므로, MusicXML 과 함께
재생용 음표 목록(`playback`)도 보냅니다. 붙임줄은 한 음으로 합치고, 셈여림은 세기(velocity)로,
스타카토는 절반 길이로, 악센트는 조금 더 세게 바꿉니다. 브라우저(`static/js/player.js`)는 이것을
실제 악기 샘플로 재생하고, 악보 위 보라색 커서가 오디오 시계에 맞춰 따라갑니다.

- 샘플은 악기당 약 3MB 입니다. 처음 재생을 누를 때 받고("소리 불러오는 중… 3/9"), 브라우저
  Cache API 에 저장해 다음부터는 바로 시작합니다.
- 4명 이상인 현악 파트는 솔로 바이올린 대신 현악 합주 샘플을 씁니다. 소리도 합주답고 받을 파일도 줄어듭니다.
- smplr 의 `stop()` 은 울리고 있는 음만 끄고 예약된 음은 남깁니다. 그래서 재생마다 출력 노드를 새로 만들고,
  정지하면 그 노드를 끊어 남은 예약이 소리 없이 지나가게 합니다.
- 재생하면 커서를 따라 페이지가 내려가므로, 제목과 재생·정지 버튼은 화면 위에 붙어 있습니다.

**로그인.** 이메일/비밀번호 인증은 브라우저의 Firebase Web SDK 만 할 수 있습니다.
브라우저는 ID 토큰을 받아 `/api/session` 에 넘긴 뒤 바로 로그아웃하고, 서버가 Admin SDK 로
토큰을 한 번 검증해 Flask 세션 쿠키로 바꿉니다. 쿠키 이름은 `aura_score_session` 입니다.
쿠키는 포트를 구분하지 않아서, 기본 이름 `session` 을 쓰면 localhost 에 같이 띄운 다른
Aura 앱과 서로 로그아웃시킵니다.

## 파일

```
app.py               라우트와 세션. login_required 가 여기 있습니다.
orchestra.py         악기 15종(음역·음자리표), 스타일·프리셋·난이도·형식·템포 선택지,
                     두 폼을 하나의 Request 로 바꾸는 검증. 폼, 프롬프트, 악보 작성이 모두 여기서 읽습니다.
templates/compose/   방식 고르기(choose), 간단하게(simple), 자세하게(detailed), 결과(result).
score_service.py     GPT 프롬프트와 JSON 스키마, OpenAI 호출과 오류 안내.
musicxml.py          마디 문자열 파싱, 자동 수정, MusicXML 작성.
firebase_setup.py    Firebase 초기화, 토큰 검증, 남은 설정 안내.
static/js/auth.js    Firebase 이메일/비밀번호 인증 → Flask 세션 인계.
static/js/compose.js 두 폼의 입력 처리, 생성 대기 표시, 악보 렌더링과 다운로드, 재생 버튼.
static/js/player.js  사운드폰트 재생, 커서 동기화, 정지.
```

아직 없는 것: 만든 악보 저장("내 악보" 목록 — 지금은 페이지를 떠나면 결과가 사라지고, 생성 중에는
떠나기 전에 경고합니다), 하프·피아노처럼 두 단 악보를 쓰는 악기, 재생 중 템포 조절이나 원하는 마디부터 재생,
곡 도중의 조표·템포 변화, 크레셴도 기호, 셋잇단음표와 피치카토.
