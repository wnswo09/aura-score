# Aura Score

악기 구성과 분위기, 템포를 고르면 GPT 가 오케스트라 총보를 써 주는 앱.

- **악보 생성**: OpenAI `gpt-6-sol` (Responses API, Structured Outputs). `.env` 에서 바꿀 수 있습니다.
- **악보 표시**: OpenSheetMusicDisplay 2.1.3, MusicXML 다운로드
- **재생**: smplr 1.0 + General MIDI 사운드폰트(MusyngKite), 악보 위 커서가 따라감
- **로그인**: Firebase Authentication, 이메일/비밀번호
- **내 악보**: 만든 곡은 끝나는 대로 Firestore 에 저장되고, 다시 열어 보고 재생하고 지울 수 있습니다

## 화면

| 경로 | 화면 | 로그인 |
|---|---|---|
| `/` | 홈 | 불필요 |
| `/signup`, `/login` | 회원가입, 로그인 (`?next=/경로` 면 로그인 후 그리로) | — |
| `/scores/new` | 입력 방식 고르기 → `?mode=simple` 또는 `?mode=detailed` 폼과 결과 악보 | **필요** |
| `POST /api/scores` | 생성 작업 시작 → 작업 id (곧바로 답함) | **필요** |
| `GET /api/scores/<id>` | 작업 진행 단계, 끝나면 악보 | **필요**, 시작한 사람만 |
| `/scores` | 내 악보 — 저장된 곡 목록, 최신순 | **필요** |
| `/scores/<id>` | 저장된 곡 하나: 설계, 악보, 재생, 다운로드, 삭제 | **필요**, 만든 사람만 |
| `GET /api/library/<id>` | 저장된 곡을 다시 조립한 악보 | **필요**, 만든 사람만 |

입력은 두 가지 방식이고, 서버에서는 같은 요청 하나(`orchestra.Request`)로 합쳐집니다.

- **간단하게** — 버튼만. 작곡가 스타일 7종(바로크·고전·베토벤·낭만·인상주의·영화음악·게임/애니 OST),
  규모(스타일에 맞게 / 작게 ~10명 / 중간 ~30명 / 크게 60명+), 분위기(최대 2개), 빠르기 3단계,
  주인공 악기(선택), 연주 시간 약 1 / 3 / 5 / 8분, 한 줄 메모. 스타일이 악기를, 규모가 인원을 정하고(`orchestra.scaled`),
  고른 결과는 폼에 "플루트 2 · … · 현악 6-5-4-3-2 (총 33명)" 처럼 바로 보입니다.
  난이도는 중급, 조성·박자는 GPT 가 고릅니다.
- **자세하게** — 악기 15종의 인원(관악은 한 줄을 나눠 쓰는 연주자 수, 현악은 파트 인원),
  조성·박자(직접 또는 맡기기), 곡 형식(A / AB / ABA / 론도), 주인공 악기(선택), 중심 템포 BPM, 연주 시간 1~10분, 스타일(선택),
  난이도, 분위기, 추가사항. 고른 조성·박자는 스키마에서 값 하나짜리 enum 이 되어 GPT 가 바꿀 수 없습니다.

현악 인원은 악보 모양을 거의 바꾸지 않습니다 (몇 명이든 한 줄). 1명이면 솔로(겹음 2개까지),
10명 이상이면 세 갈래 divisi 까지 허용하는 식으로 동시에 낼 수 있는 음 수에만 반영됩니다.

## 준비

```bash
cp .env.example .env
```

`.env` 에 채울 것:

1. **Firebase Admin 키** — Firebase Console > 프로젝트 설정 > 서비스 계정 > 새 비공개 키 생성 →
   `serviceAccountKey.json` 으로 이 폴더에 저장. (`.gitignore` 에 들어 있습니다. 절대 커밋하지 마세요.)
2. **Firebase 웹 설정** — 프로젝트 설정 > 일반 > 내 앱 > 웹 앱의 `apiKey` / `authDomain` / `projectId`.
   키 파일과 같은 프로젝트여야 합니다. 다르면 화면 위 배너가 알려 줍니다.
3. **이메일/비밀번호 로그인 켜기** — Authentication > Sign-in method > 이메일/비밀번호 > 사용 설정.
4. **OPENAI_API_KEY** — https://platform.openai.com/api-keys 에서 만든 키.
   `OPENAI_MODEL`(기본 `gpt-6-sol`) 과 `OPENAI_REASONING_EFFORT`(기본 `medium`) 는 선택입니다.
5. **FLASK_SECRET_KEY** — `python3 -c "import secrets; print(secrets.token_hex(32))"` 로 만든 값.

설정이 덜 끝나면 화면 위에 무엇이 남았는지 배너로 뜹니다.

`gpt-6-sol` 기준으로 5분짜리 15파트 곡 하나에 약 2분 20초, 토큰 입력 1.9만 / 출력 3.3만이 들었습니다.
곡마다 걸린 시간, 토큰 수, 자동 수정 개수, 반복도가 서버 로그에 `score: ...` 한 줄로 남습니다.
`OPENAI_PLAN_EFFORT`(기본 `high`) 는 설계 호출의, `OPENAI_REASONING_EFFORT`(기본 `medium`) 는 장 작성 호출의 추론 강도입니다.

python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

## 동작 방식

**GPT 는 MusicXML 을 쓰지 않습니다.** 오케스트라 총보를 MusicXML 로 쓰면 수천 줄이고,
어디 한 군데만 틀려도 파일 전체가 깨집니다. 대신 마디마다 짧은 문자열 하나를 씁니다.

```
"@p C4:4( D4:8 E4:8 F4:4 G4:4)"     셈여림 p, 이음줄 시작, 4분·8분음표…
"G4+B4:2. r:4"                      화음(점2분) + 4분쉼표
"E5:2~ E5:8 D5:8 C5:4"              붙임줄
"R"                                 온마디 쉼표
```

음높이는 모두 실음(Score in C)입니다. 서버(`musicxml.py`)가 이 문자열을 읽어 MusicXML 로
바꾸면서 모델이 실제로 자주 내는 실수를 고칩니다:

- 마디 박자 합이 모자라면 쉼표로 채우고, 넘치면 마디선에서 자릅니다.
- 악기 음역 밖의 음은 옥타브를 옮겨 안으로 넣습니다 (초급은 더 좁은 음역).
- 편성 인원보다 많은 화음은 바깥 성부(맨 위·맨 아래)만 남깁니다.
- 음이 다른 붙임줄, 짝이 없는 이음줄은 지웁니다.
- 마디 수가 다르거나 빠진 파트는 쉼표로 채우고, 곡 전체가 400마디를 넘으면 자릅니다.
- 끝에 아무도 연주하지 않는 마디는 잘라 내고, 마지막 마디에서 모두가 일찍 끊으면 마디 끝까지 늘입니다.
- 직전과 같은 셈여림 기호는 지웁니다 (두 마디 넘게 쉬고 들어올 때는 남깁니다).

고친 개수는 악보 위에 "N군데를 자동으로 고쳤습니다" 로 표시됩니다.

**긴 곡은 장으로 나눠, 설계 한 번 + 장마다 한 번씩 씁니다.** 오케스트라 곡다운 길이(5분 이상)를
GPT 한 번의 응답으로 쓰게 하면 앞에서 쓴 것을 다시 꺼내 씁니다. 그래서 두 단계로 나눴습니다 (`score_service.generate`).

1. **설계** (`prompts.PLAN`, 추론 강도 high) — 곡 전체를 4~6개의 장으로 나누고, 장마다 템포·조성·목적·
   시작과 끝을 정합니다. 주제 선율 2~3개(A 주인공, B 대비, C 후반부에만 나오는 새 재료)는 실제 음표로
   씁니다. 장 안의 구간마다 어떤 주제를 어떻게 바꿔 쓸지(`material`)도 정합니다.
2. **장 작성** (`prompts.CHAPTER`) — 장마다 따로, 모두 동시에. 각 호출은 전체 설계와 주제 악보, 앞뒤 장이
   어떻게 끝나고 시작하는지만 받아 자기 장을 씁니다. 마지막 장이 아니면 마침꼴로 끝내지 못하게 해서
   중간에 곡이 끝난 것처럼 들리지 않게 합니다. 실패한 장은 한 번 더 시도합니다.
3. **조립** (`musicxml.build`) — 장들을 이어 붙이고, 장이 바뀌는 곳에 조표·템포·장 제목·겹세로줄을 넣습니다.

장마다 템포와 조성이 바뀌므로 재생 시간표는 초 단위로 보냅니다. 커서는 서버가 보낸 기준점
(`anchors`: 악보 박 → 초)으로 장마다 다른 템포와 끝맺음의 느려짐을 따라갑니다.
몇 분씩 걸리므로 생성은 백그라운드 작업(`jobs.py`)으로 돌고, 화면은 2초마다 진행 단계를 묻습니다
("5개 장을 동시에 쓰는 중 (3/5 완성)"). 작업 id 는 탭에 기억해 두어, 생성 중에 다른 페이지에 다녀와도
이어서 보여 줍니다. 작업은 서버 메모리에 있어서 서버를 다시 켜면 사라집니다.

5분짜리 곡 하나를 재 보니: 5장 119마디 5분 2초, 장마다 템포(100 → 84 → 120 → 72 → 100)와
조성(G단조 → B♭장조 → D단조 → E♭장조 → G단조)이 바뀌고, 앞 장의 마디를 그대로 베낀 것은 음표 기준 6% 였는데
그중 거의 전부가 베이스의 긴 음이었습니다.

**장 안에서는 설계도를 먼저 쓰고, 구간 단위로 씁니다.** 처음에는 GPT 가 계획 없이 악기별로 처음부터 끝까지 썼고,
32마디를 달라고 하면 네 화음을 여덟 번 돌렸습니다. 지금은 응답 형식의 순서가 곧 작업 순서입니다.

구간마다 역할(도입·주제·대비·전개·솔로·절정·재현·종결), 마디 수, 선율 악기, 짜임, 반주 종류, 셈여림,
쓸 재료, "여기서 새로 일어나는 일" 한 문장을 설계에서 정하고, 장 작성은 구간 단위로 모든 악기를 함께 씁니다.

지시문은 되돌아오는 선율을 반드시 바꾸게 하고, 이웃한 구간이 같은 반주를 쓰지 못하게 하고,
주인공 악기에게 솔로를 한 번, 다른 악기에게도 솔로를 한 번 줍니다. 솔로와 절정의 위치는 요청마다
여섯 가지 서사 형태(`orchestra.SHAPES`) 중 하나를 무작위로 줘서, 곡마다 같은 틀이 나오지 않게 합니다.
설계는 결과 화면에 장별로 보이고, 악보에는 구간 기호(A, B, … 장을 넘어 이어짐)와 Solo / tutti 로 들어갑니다.
섹션 단위로 연주하는 악기의 솔로는 재생할 때 솔로 악기 샘플로 납니다.

서버는 반복을 숫자로 잽니다(`musicxml._repetition`): 한 파트 안에서 앞 마디를 그대로 베낀 마디에 든
음의 비율. 같은 조건의 32마디 두 곡에서 59% → 21~24%, 33% → 11~15% 로 줄었습니다. 리듬만 같은
마디의 비율은 74~82% 로 여전히 높은데, 한 구간 안에서 반주가 같은 리듬을 유지하는 것까지 세기 때문입니다.

**끝맺음은 쓰는 것과 연주하는 것, 둘 다입니다.** 음표만 정확한 박자로 틀면 곡이 그냥 멈춥니다.

- 쓰기: 마지막 장의 마지막 구간은 새로운 것을 시작하지 않고, 딸림화음으로 준비한 뒤 선율이 첫 박에
  도착하는 으뜸화음을 한두 마디 끕니다. 길이는 분 단위 목표라 마디 수는 끝맺음에 맞춰 정해집니다.
- 고르기: GPT 가 끝맺음 방식을 정합니다 — 느려지며 / 사라지듯 / 힘 있게 (`orchestra.ENDINGS`).
- 표기: 악보에 `rit.` 와 늘임표가 들어갑니다.
- 연주: 재생 시간표가 끝에서 늘어납니다. 마지막 화음을 치는 마디의 한두 마디 전부터 느려지고,
  화음은 적힌 길이와 상관없이 초 단위로 정한 길이(느려지며 4~6초)만큼 울리며 서서히 줄어듭니다.
  커서는 서버가 보낸 기준점(`anchors`)으로 늘어난 시간을 따라갑니다.

사운드폰트의 음은 모두 3초짜리 녹음이라, 그보다 긴 음은 허공에서 끊깁니다 (느린 템포의 온음표, 마지막 화음).
`player.js` 는 긴 음을 1.5초마다 조금 약하게 다시 겹쳐 쳐서 끝까지 잇습니다. 활을 바꾸는 것과 비슷합니다.

**스키마로 막을 수 있는 건 스키마로 막습니다.** 응답의 악기 이름은 고른 악기만,
조성은 난이도에 맞는 것만(초급은 조표 2개 이하) 나오도록 요청마다 JSON 스키마를 새로 만듭니다.

**기보 규칙.** 피콜로와 콘트라베이스는 관례대로 옥타브를 옮겨 적고, 음자리표는 파트의 음역을
보고 고릅니다 (비올라 알토, 첼로가 높으면 테너 등). 6/8 박자에서는 점4분음표를 한 박으로
템포를 표시합니다.

**재생.** 서버는 악보를 쓰면서 이미 모든 음의 실제 높이와 길이를 알고 있으므로, MusicXML 과 함께
재생용 음표 목록(`playback`)도 보냅니다. 붙임줄은 한 음으로 합치고, 셈여림은 세기(velocity)로,
스타카토는 절반 길이로, 악센트는 조금 더 세게 바꿉니다. 브라우저(`static/js/player.js`)는 이것을
실제 악기 샘플로 재생하고, 악보 위 보라색 커서가 오디오 시계에 맞춰 따라갑니다.

- 샘플은 악기당 약 3MB 입니다. 처음 재생을 누를 때 받고("소리 불러오는 중… 3/9"), 브라우저
  Cache API 에 저장해 다음부터는 바로 시작합니다.
- 4명 이상인 현악 파트는 솔로 바이올린 대신 현악 합주 샘플을 씁니다. 소리도 합주답고 받을 파일도 줄어듭니다.
- smplr 의 `stop()` 은 울리고 있는 음만 끄고 예약된 음은 남깁니다. 그래서 재생마다 출력 노드를 새로 만들고,
  정지하면 그 노드를 끊어 남은 예약이 소리 없이 지나가게 합니다.
- 재생하면 커서를 따라 페이지가 내려가므로, 제목과 재생·정지 버튼은 화면 위에 붙어 있습니다.

**내 악보.** 생성 작업은 끝나면 곡을 Firestore 에 저장합니다 (`library.py`,
`score_libraries/{uid}/scores/{id}`). 저장하는 것은 MusicXML 이 아니라 GPT 가 쓴 원본(설계 + 장별 마디 문자열,
zlib 압축)과 입력한 폼입니다. 5분짜리 곡의 MusicXML 은 472KB 로 Firestore 문서 한도(1MB)의 절반인데,
원본은 압축하면 8KB 입니다. 곡을 열 때 `musicxml.build` 로 다시 조립하므로(5분짜리가 0.02초)
악보 작성 코드를 고치면 예전 곡에도 반영됩니다. 사용자마다 컬렉션이 따로라 남의 곡에는 닿을 수 없고,
목록은 단일 필드 정렬이라 복합 색인이 필요 없습니다. 목록 쿼리는 원본을 빼고 요약 필드만 읽습니다.
저장에 실패해도 곡은 화면에 보여 주고, 저장하지 못한 이유를 알려 줍니다.

**로그인.** 이메일/비밀번호 인증은 브라우저의 Firebase Web SDK 만 할 수 있습니다.
브라우저는 ID 토큰을 받아 `/api/session` 에 넘긴 뒤 바로 로그아웃하고, 서버가 Admin SDK 로
토큰을 한 번 검증해 Flask 세션 쿠키로 바꿉니다. 쿠키 이름은 `aura_score_session` 입니다.
쿠키는 포트를 구분하지 않아서, 기본 이름 `session` 을 쓰면 localhost 에 같이 띄운 다른
Aura 앱과 서로 로그아웃시킵니다.

## 파일

```
app.py               라우트와 세션. login_required 가 여기 있습니다.
orchestra.py         악기 15종(음역·음자리표), 스타일·프리셋·난이도·형식·템포 선택지,
                     두 폼을 하나의 Request 로 바꾸는 검증. 폼, 프롬프트, 악보 작성이 모두 여기서 읽습니다.
templates/compose/   방식 고르기(choose), 간단하게(simple), 자세하게(detailed), 결과(result).
templates/library.html, score.html  내 악보 목록, 저장된 곡 하나.
prompts.py           GPT 지시문(설계용, 장 작성용), 요청문, JSON 스키마.
score_service.py     설계 호출 → 장 동시 작성 → 조립. OpenAI 호출과 오류 안내.
jobs.py              생성 작업을 백그라운드에서 돌리고 진행 단계를 기억합니다.
library.py           내 악보: Firestore 에 저장, 목록, 다시 조립해 열기, 삭제.
musicxml.py          마디 문자열 파싱, 자동 수정, 장 조립(조표·템포 변화), MusicXML 작성, 재생 시간표.
firebase_setup.py    Firebase 초기화, 토큰 검증, Firestore 클라이언트, 남은 설정 안내.
static/js/auth.js    Firebase 이메일/비밀번호 인증 → Flask 세션 인계.
static/js/compose.js 두 폼의 입력 처리, 생성 작업 시작과 진행 표시.
static/js/score_view.js 완성된 곡 보여 주기(장별 설계, 악보, 재생 버튼, 다운로드). 작곡 페이지와 저장된 곡 페이지가 같이 씁니다.
static/js/player.js  사운드폰트 재생, 커서 동기화, 정지.
```

셋잇단음표와 피치카토.
